# Model card: MHT-CET cutoff and admission-probability model

## Task
Predict the cutoff percentile of a (college, branch, category, seat source, round) and convert it into
P(student with percentile *p* is admitted).

## Data
`data/combined_cutoffs.csv`: 49,180 cutoff rows, 366 colleges, CAP rounds 1-4. Parsed from the published
CAP cutoff lists. Target is `percentile`.

## Method
RandomForest + four HistGradientBoosting regressors (different seeds/depths/learning rates), blended by non-negative
least squares on an internal validation carve-out of the training data (weights: the HGB models carry about 92%,
the forest about 8%). A second boosted model predicts per-row |error| (sigma, clipped to 4-30 points).
Isotonic regression on `z = (p − predicted)/sigma`, fitted on a disjoint calibration slice, gives probabilities.
College code (366 values) is target-encoded with smoothing 25, fit on training rows only.

Split: 64% fit, 16% calibration, 20% untouched test.

## Evaluation protocol (leak-free)
For each held-out row, synthetic students are placed at offsets −25..+25 (step 5) around that row's real cutoff.
Ground truth is `student ≥ real cutoff`. The prediction uses only the model's predicted cutoff and sigma; the real
cutoff of that row never enters it.

## Why overall accuracy is about 82%, not 95%
1. **Noise floor.** For the same college/branch/category, the cutoff changes by a median 5.4 and mean 11.3
   percentile points between consecutive rounds (90th percentile 30.9). Even the naive "same as last round" predictor
   has MAE 11.3; the ensemble (10.8) is already better than that.
2. **Boundary cases.** A student exactly at the cutoff is a coin flip for any unbiased predictor, which caps overall
   accuracy near 95% even if every other case were perfect.
3. **Little history.** 15,629 of 28,693 college/branch/category groups appear in a single round only. Adding the
   previous round's cutoff as a feature helped only marginally (MAE 10.78 → 10.64).

The only honest way to quote 95%+ is with coverage, as in the selective-prediction table.

## Evaluation leak found and fixed
An earlier evaluation scored students against `(actual_cutoff + prediction) / 2`, which feeds the held-out label into the
predictor and inflated accuracy by about 8 points (the 86-90% figures from earlier iterations are invalid).
`experiments/explore_lag_and_leak.py` reproduces both versions side by side. The current code and `metrics.json`
use the leak-free protocol only. Likewise `sml_rank` (correlation −0.98 with the target) is never used as a feature.

## Intended use and limits
- Ranking colleges by likelihood of admission for a given percentile/category; showing safe / moderate / ambitious options.
- Not a guarantee. Round-to-round shifts of 10+ points are common and unpredictable from past data alone.
- Weak on colleges not in the training data (R² 0.12), so new colleges need data before they can be ranked.
- Precision@K style metrics are not reported here: ranking by probability puts the safest colleges first, so that
  number says little about quality.
- Data covers four CAP rounds of a single cycle; new cycles should be added and the model retrained.
